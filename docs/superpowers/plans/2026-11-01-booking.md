# Booking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A visitor books a free 30-minute call in a week view on antonwester.se, and gets a Google invite with a Meet link.

**Architecture:** The Astro site gets two static pages with a small client script. The existing Worker gets `GET /api/booking/slots` and `POST /api/booking`, which call Google Calendar with `fetch`. Slot logic is a pure module, so it can be tested without Google.

**Tech Stack:** Astro 7, plain JS Cloudflare Worker, Google Calendar API v3, Cloudflare Turnstile, vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-booking-design.md`

## Global Constraints

- No new runtime dependency. The Worker runs without `nodejs_compat`.
- Bookable Mon–Fri 09:00–17:00 Europe/Stockholm, slots every 30 minutes, last start 16:30.
- A slot's 30 minutes plus 15 on each side must touch nothing busy.
- Earliest 24 hours ahead, latest 4 weeks ahead.
- Primary calendar only.
- Cap: 10 upcoming site bookings, one per email address. Events carry private extended property `source=site`.
- Event title and description are fixed text with no visitor text.
- No Google secret reaches the browser.
- Secrets: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REFRESH_TOKEN`, `TURNSTILE_SECRET`.
- Scopes: `calendar.events` and `calendar.freebusy`.
- All visitor copy in sv and en, through the human-writing skill.

## Review Focus

- A forged `start` (off the grid, weekend, past, with an offset, not a date) gets 400 and no Google write. Test in Task 3.
- `week=garbage` or a week outside the window gets 400 or an empty list, not a 500. Test in Task 3.
- Email case: `A@x.se` and `a@x.se` count as the same address for the cap. Test in Task 3.
- A visitor far from Sweden: a slot can fall on another local day, even a Saturday. It must still be shown. Test in Task 4 through `groupByDay`.
- The mail to Anton fails after the event is created: the visitor still gets success. Test in Task 3.

  - Monday `2026-10-26` (day after the autumn change) first slot is `...T08:00:00.000Z`. Monday `2026-10-19` first slot is `...T07:00:00.000Z`. Thursday `2027-03-25` is `T08:00`, and Monday `2027-03-29` is `T07:00` (spring change is `2027-03-28`).
